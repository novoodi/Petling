# Petling 출시 체크리스트 (처음 하는 사람용)

아래 순서대로 하나씩 하면 됩니다. 각 단계는 "왜 → 어떻게 → 주의"로 정리했습니다.
코드 쪽 작업(서명 설정, R8, 데이터 안전 등)은 이미 끝나 있고, 여기 있는 건 **사람이 직접 해야 하는 외부 작업**입니다.

---

## 1. Google Play 개발자 계정 만들기 (제일 먼저)

**왜:** 이게 있어야 앱을 올릴 수 있고, 계정 종류에 따라 출시 조건이 달라져서 일정 계획의 출발점입니다.

**어떻게:**
1. https://play.google.com/console 접속 → Google 계정으로 로그인
2. 개발자 등록(등록비 **$25, 1회성**) 결제
3. 계정 종류 선택: **개인(personal)** vs **조직(organization)**

**주의 (중요):**
- **2023년 11월 이후에 만든 개인 계정**은 정식 출시 전에 **테스터 12명 이상 + 14일간 비공개 테스트**를 반드시 거쳐야 정식 출시 권한이 열립니다.
- 즉 "오늘 만들고 내일 전면 출시"는 개인 계정이면 불가능할 수 있습니다. 계획을 최소 2~3주로 잡으세요.
- 조직 계정은 이 제약이 없지만 사업자등록번호(D-U-N-S) 등이 필요합니다.

## 2. 앱 아이콘 만들기

**왜:** 현재는 안드로이드 기본 초록 로봇 아이콘이라 이대로 출시하면 안 됩니다. 스토어 등록에도 512×512 아이콘이 필요합니다.

**어떻게 (가장 쉬운 방법):**
1. 캐릭터 "모도리" 기반으로 **512×512 PNG** 아이콘 이미지 1장 준비 (직접 그리거나, 디자이너/생성툴 이용)
2. Android Studio에서: 좌측 `app` 우클릭 → **New → Image Asset**
3. Foreground를 준비한 이미지로 지정, 배경색 지정 → Next → Finish
   - 이러면 `mipmap-*` 아이콘들이 자동 교체됩니다.
4. 스토어용 512×512 아이콘 파일은 따로 보관 (Play Console 등록 때 업로드)

**주의:** 아이콘 여백/잘림은 Image Asset 미리보기로 확인. 캐릭터가 원 안에 잘 들어오게.

## 3. 업로드 키스토어(서명 키) 만들기

**왜:** 안드로이드 앱은 "서명"이 있어야 설치·업로드됩니다. 이 키가 "이 앱은 나(개발자)의 것"이라는 증명입니다.

**어떻게:**
1. Android Studio가 깔려 있으면 `keytool`이 이미 있습니다. 터미널(PowerShell)에서 프로젝트 폴더로 이동 후 실행:
   ```
   keytool -genkeypair -v -keystore petling-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias petling
   ```
   - `keytool`이 "명령을 찾을 수 없음"이면, Android Studio의 JDK 경로를 쓰세요. 보통:
     `"C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe"` (앞에 `& ` 붙여 실행)
2. 물어보는 것들:
   - 키스토어 비밀번호(두 번) → **꼭 기억/기록**
   - 이름/조직/도시/국가(KR) → 대충 입력해도 됨(공개 안 됨)
   - 키 비밀번호 → 엔터 치면 키스토어 비밀번호와 동일하게 설정 가능
3. 생기면 `petling-upload.jks` 파일을 **프로젝트 루트**(`E:\Petling`)에 둡니다.
4. `keystore.properties.template`을 복사해서 같은 폴더에 **`keystore.properties`** 로 저장하고 값을 채웁니다:
   ```
   storeFile=petling-upload.jks
   storePassword=(방금 정한 비밀번호)
   keyAlias=petling
   keyPassword=(키 비밀번호, 같게 했으면 위와 동일)
   ```

**주의 (매우 중요):**
- `petling-upload.jks`와 비밀번호를 **잃어버리면 안 됩니다.** 안전한 곳(비밀번호 관리자 등)에 백업하세요.
- 이 파일들은 이미 `.gitignore`에 있어 실수로 커밋되지 않습니다(비밀 유출 방지).
- Play "앱 서명" 기능을 쓰면 최종 서명키는 Google이 관리하고, 이 키는 "업로드 키"로만 쓰여 분실 시 재설정이 가능합니다(그래도 백업 권장).

## 4. Firebase(크래시 리포팅) 연결

**왜:** 출시 후 앱이 어디서 튕기는지(크래시) 봐야 고칠 수 있습니다. 이게 없으면 깜깜이 운영입니다.

**어떻게:** `docs/CRASHLYTICS_SETUP.md`에 5단계로 정리돼 있습니다. 요약:
1. https://console.firebase.google.com → 프로젝트 생성(무료)
2. 안드로이드 앱 추가 — **패키지명 `com.novoodi.petling`** (꼭 일치)
3. `google-services.json` 다운로드 → `app/google-services.json`에 저장
4. 문서의 Gradle 2~3단계대로 플러그인/의존성 추가 (제가 정확한 코드 조각을 문서에 넣어놨습니다 — 그대로 복붙)
5. Firebase 콘솔에서 Crashlytics 켜기

**주의:** `google-services.json`이 없으면 이 플러그인이 빌드를 깨므로, **파일을 넣은 뒤에** Gradle 코드를 추가하세요. (지금은 안 넣은 상태로 두어 빌드가 정상입니다.)

## 5. 개인정보 처리방침 공개 URL 만들기

**왜:** 마이크·사진 권한을 쓰는 앱은 Play 심사에서 처리방침 URL이 **필수**입니다.

**어떻게:**
1. `docs/PRIVACY_POLICY_ko.md`를 엽니다. 맨 위 `시행일`, 맨 아래 `문의 이메일`을 채웁니다.
2. 이 내용을 공개 웹페이지로 올립니다. 초보자에게 가장 쉬운 방법:
   - **Notion**: 새 페이지에 내용 붙여넣기 → 우측 상단 "공유" → "웹에 게시" → 나온 URL 사용 (가장 쉬움)
   - 또는 GitHub Pages, Google Sites 등
3. 그 URL을 Play Console 등록 때 "개인정보처리방침" 칸에 넣습니다.

**주의:** 처리방침 내용은 **실제 앱 동작에 맞게** 이미 작성돼 있습니다(온디바이스 처리 + Crashlytics 익명 로그만 외부 전송). 임의로 "아무 데이터도 안 보냄"으로 바꾸면 Crashlytics와 모순되어 심사 리스크가 생깁니다.

## 6. 릴리스 빌드 만들고 실기기에서 확인

**왜:** 스토어에 올릴 최종 파일(AAB)을 만들고, 실제 폰에서 잘 도는지 마지막 점검.

**어떻게:**
1. 3~4단계(키스토어 + Firebase) 끝난 뒤, 터미널에서:
   ```
   ./gradlew :app:bundleRelease
   ```
   → `app/build/outputs/bundle/release/app-release.aab` 생성 (이게 스토어 업로드 파일)
2. 실기기 테스트용 서명 APK: `./gradlew :app:assembleRelease` → APK를 폰에 설치해 확인
3. **꼭 확인할 시나리오:**
   - 스크린샷 찍고 → "정리할까요?" 알림 → 정리 동작
   - 갤러리 이미지 공유 → 일정/정보 추출 → 저장
   - 음성으로 일정 등록
   - 일정 시간에 캐릭터 알림이 실제로 뜨는지 (배터리 최적화 켠 상태에서도)
   - 재부팅 후에도 알림이 유지되는지
   - Gemini Nano 미지원 폰에서도 폴백으로 저장되는지 (가능하면 저사양 폰 1대)

**주의:** 크래시가 아니라 "그냥 안 됨"(알림이 안 옴 등)이 학생폰마다 다를 수 있어, 가능하면 삼성/샤오미 등 2~3종에서 봐주세요.

---

## 7. Play Console에 등록하고 비공개 테스트 → 출시

**어떻게:**
1. Play Console → 앱 만들기 → 이름(Petling), 언어(한국어), 무료 앱 선택
2. 필수 항목 입력:
   - 앱 아이콘(512×512), 스크린샷(폰 2장 이상), 짧은 설명/자세한 설명
   - **개인정보처리방침 URL** (5단계)
   - **데이터 안전(Data safety)** 양식: "Crashlytics 진단 정보 수집(익명)"만 신고, 나머지는 "기기에서만 처리"
   - 콘텐츠 등급 설문, 타겟 연령(학생 대상)
3. **비공개 테스트 트랙**에 AAB 업로드 → 테스터 12명 이상 초대(이메일) → 14일 운영
   - 이 기간에 리텐션/파싱정확도/알림 이행 같은 지표를 관찰
4. 조건 충족 후 **정식 출시 신청** → 단계적 배포(처음 5~10%로 시작해 문제없으면 올리기) 권장

## 순서 요약 (의존 관계)

```
1. Play 계정 ─┐
2. 앱 아이콘 ─┤
3. 키스토어 ──┼─→ 6. 릴리스 빌드 + 실기기 QA ─→ 7. Play 등록 → 비공개 테스트(14일) → 정식 출시(단계적)
4. Firebase ─┤
5. 처리방침 ─┘
```

막히는 단계가 있으면 그 단계만 짚어 물어보세요. 명령어 오류·화면 캡처 해석 등 같이 봐드릴게요.
